## Verbatim verdict

FINDINGS:
- **Blocking: `orchestrator_route` sets `created_by=router` with a process-wide mock patch.** orchestrator_tools.py:26 imports `unittest.mock.patch` in production code. Line 180 then runs `patch.object(kanban_tools, "_persisted_identity", return_value="router")` around `_handle_create`. That swaps a module-global function, so it affects the whole process, not just this call. While it is in place, any other `kanban_create` or `kanban_comment` running in the same gateway process is also recorded as `router` (kanban_tools.py:970 and line 1149 both read `_persisted_identity()`). Records that did not come from the router get stamped `router`. That breaks "stamps created_by=router", and it is the authorship forgery that `_persisted_identity`'s own docstring warns against (kanban_tools.py:139-148, #19713). The repo's own validator also flags `patch.object` on core modules as a core override (hermes_cli/plugin_validate_core_override.py:220).
- **Blocking: `orchestrator_reply` can skip the anchor's profile-scoped adapter lookup.** In `_deliver_subscription_reply`, an `AttributeError` from `_adapter_for_subscription` makes the code fall back to the primary adapter, `runner.adapters.get(plat)`. The anchor (notes/p1-1-anchors.md §4, line 191) requires `_adapter_for_subscription` "respecting `profile_routes` and multi-tenant scoping". That function exists precisely to avoid "turning a missing secondary bot into primary authority" (kanban_watchers_notifier.py:163). The fallback lets a reply go out through the wrong bot or profile. This departs from the anchored send path.

## Supervisor disposition

FAIL stands. Fix round 1 (packet p1-2-fix1) requires:
1. Remove `unittest.mock` from production code entirely. `orchestrator_route` must create the task through the kanban DB-layer creation path (the same one `kanban_create` uses) with `created_by="router"` passed as data — no patching of `_persisted_identity` or any shared function.
2. `orchestrator_reply`: remove the primary-adapter fallback. If `_adapter_for_subscription` raises or returns no adapter, fail closed with an error result; never send through a different profile's adapter.
3. Remove the `_ORIG_*` test-scaffolding sentinel code from production code.
4. `orchestrator_route`: drop the silent `kanban.default_assignee` fallback so the schema's required `assignee` is honored (error if absent).
Card 1.3's tests will then assert: the router stamp lands on the routed task only, reply fails closed when the adapter lookup errors, and the previously verified gating behavior. Re-review by Opus on the fix commit.
