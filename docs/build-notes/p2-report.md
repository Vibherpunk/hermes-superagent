## 4. Telegram Finding Summary (Card 2.11)

<!-- no-tmp: ok — historical supervisor evidence artifact in tmp -->
The supervisor's filed audit report (`EVIDENCE-p2-2.11-telegram.md` in the executor pack, derived from `/tmp/p2-11-finding.md`) establishes the operational realities for Telegram triggers under default configuration:

1. **Privacy Mode Blocks Unaddressed Group Messages Upstream**:
   Although Hermes's Telegram adapter requests `allowed_updates=Update.ALL_TYPES`, the upstream Telegram Bot API servers enforce Bot Privacy Mode by default on all bots. Under default privacy mode, Telegram servers drop all ordinary group chatter before delivery. Only messages explicitly addressing the bot (@mentions, direct quote replies, or `/` slash commands) ever reach the gateway.
2. **Admission Table Inertia for Unaddressed Group Cells**:
   Because unaddressed group messages never reach the gateway webhook or polling streams, Superagent admission table cells where `source="telegram"`, chat is a group, and `addressed=False` (triggers that would evaluate to `strength="inferred"` with `via="admission"`) remain completely inert until manual intervention occurs.
3. **Trigger Scope Derivation**:
   On Telegram sources, `scope_id` and `guild_id` are absent. Consequently, the trigger `scope` resolves directly to `source.chat_id`:
   - **DM Scope**: Positive numeric string representing the user's ID (e.g. `"123456789"`), or normalized policy scope `'telegram:dm'`.
   - **Group Scope**: Negative numeric string representing the group or supergroup chat ID (e.g. `"-1001234567890"`).
4. **Human Action Required for Unaddressed Group Ingestion**:
   Disabling privacy mode or promoting the bot to group administrator is strictly a manual step performed by a human operator in [@BotFather](https://t.me/BotFather) (`/mybots` → Bot Settings → Group Privacy → Turn off). No configuration or BotFather settings were altered during this build.

## 5. Recorded Deviations

1. **E-044 Schema Amendment (`sa_mandates.ticket_id` Not Unique)**:
   In Card 2.2 (`0634d3e1ee5`), `sa_mandates` was initially declared with `ticket_id TEXT NOT NULL UNIQUE`. During Card 2.6 (`d5c25fd7d47`), implementation of D-1 mandate amendments (`amend_mandate`) revealed that an amendment creates a new mandate row with `amended_from = old_mandate_id` for the same `ticket_id`, marking the prior mandate `superseded`. Under Card 2.2fix (`ab87432bcfa`), the canonical schema definition in `hermes_cli/kanban_db.py` was amended to drop `UNIQUE` from `ticket_id`, enabling multi-row amendment chains.
2. **Card 2.10 Cross-Tree Stub Replacement & Fix Round**:
   Card 2.10 replaced the eight Phase 1 tool stubs in `tools/orchestrator_tools.py` with active implementations backed by `hermes_cli/orchestrator.py`. For `thread_unsubscribe`, the spec referenced `superagent_subscriptions.py`, which is developed by Lane D on branch `superagent-p3` and was absent from this worktree. Direct SQL deletion against `sa_subscriptions` was implemented with explicit integration comments. Following review findings by Claude Sonnet 5.5, Card 2.10fix (`ca56e284c0`) resolved the follow-ups: removed unhandled `task_id` from the schema, eliminated speculative imports, enforced semantic refusals on already-dismissed or already-ticketed decisions, and returned proper observe-mode payloads (`accepted: false, would_accept: true, ticket_id: null`).
3. **Observe Mode & Live Invariant Protection**:
   `superagent.enabled` remains `false` across all profiles, system configuration files, and `DEFAULT_CONFIG`.
